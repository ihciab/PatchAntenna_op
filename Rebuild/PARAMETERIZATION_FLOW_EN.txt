Parameterization Flow Documentation (English)
Purpose: a compact context document for developers and large language models to understand the current "structure image -> parametric curve JSON" pipeline.

======================================================================
1. One-Sentence Overview
======================================================================

The current parameterization pipeline takes a structure image or a repaired structure image, extracts usable centerline/boundary paths, decomposes each path into semantic curve primitives, fits each primitive as line, arc, or spline, and writes JSON, SVG, metrics, and a visualization PNG.

The most important current design choice:
For grayscale pipeline repair_fig.png images, thick strokes are no longer traced with Canny edge contours.
Direct edge tracing turns one thick stroke into two parallel boundaries and creates a messy double-layer parameterization.
The current default is stroke_mask: treat thick strokes as foreground solids first, then extract a single centerline skeleton.

======================================================================
2. Key Files
======================================================================

1. Rebuild/NewParams.py
   - Main external entry point for parameterization.
   - Defines NewParams and CurveParameterizer.
   - NewParams handles image preprocessing and edge/foreground mask extraction.
   - CurveParameterizer calls vtracer_python.py and formats JSON/PNG outputs.

2. vtracer_python.py
   - Main parameterization algorithm implementation.
   - Handles binarization, skeletonization, path ordering, resampling, keypoint detection, dynamic-programming segmentation, line/arc/spline fitting, metrics, and intermediate debug outputs.

3. fss_parameterized_cst_pipeline.py
   - One of the FSS end-to-end pipeline entry points.
   - _parameterize_repair_image() calls:
     NewParams(repair_path, save_dir=param_dir)
     params.parameterize(save_dir=param_dir)
     parameterizer.save_json(...)
     parameterizer.visualize(...)

4. parameterized_json_to_cst.py
   - Builds CST geometry from the parameterization JSON.
   - It consumes parameterization results; it does not perform image parameterization.

======================================================================
3. External Inputs and Outputs
======================================================================

Typical input:
- repair_fig.png
  A cleaned/repaired structure image from the pipeline. It is usually grayscale; gray strokes represent PEC/structure geometry.
- Or a normal structure image.

Typical output directory:
- pipeline_runs/<run_id>/02_parameterization/

Main output files:
- repair_fig_edges.png
  Preprocessing result from NewParams.
  Note: despite the name "edges", when edge_representation=stroke_mask this file is actually a foreground stroke mask.

- repair_fig_trace_input.png
  Temporary trace input image written by CurveParameterizer.

- repair_fig.svg
  SVG generated by VTracerPython.

- repair_fig_metrics.json
  Quality metrics such as component_count, total_semantic_segments, total_line_segments, total_arc_segments, total_curve_segments, and fitting errors.

- curve_parameterization.json
  The most important structured output.
  The downstream CST builder mainly consumes this file.

- curve_parameterization.png
  Visualization output.
  The left side is usually the original image; the right side shows fitted semantic curves:
  line, arc, spline, and red component start points.

- intermediates/
  Intermediate debug outputs for each component.
  The most important file is component_xxx/semantic_debug.json.

======================================================================
4. Overall Call Chain
======================================================================

Typical code:

    from Rebuild.NewParams import NewParams

    params = NewParams(repair_path, save_dir=param_dir)
    parameterizer = params.parameterize(save_dir=param_dir)
    parameterizer.save_json(param_dir / "curve_parameterization.json")
    parameterizer.visualize(param_dir / "curve_parameterization.png")

Core call chain:

    NewParams.__init__()
        -> NewParams.process()
            -> read image
            -> convert to normalized gray
            -> Gaussian blur
            -> _extract_edges()
            -> save repair_fig_edges.png

    NewParams.parameterize()
        -> decide edge_contour_tracing
        -> CurveParameterizer(...)

    CurveParameterizer.parameterize()
        -> _prepare_trace_image()
        -> build TraceConfig
        -> VTracerPython(cfg).to_svg(...)
        -> load metrics
        -> load intermediates/component_xxx/semantic_debug.json
        -> normalize semantic segments

    CurveParameterizer.save_json()
        -> write curve_parameterization.json

    CurveParameterizer.visualize()
        -> write curve_parameterization.png

======================================================================
5. NewParams Preprocessing Logic
======================================================================

NewParams converts the input image into a binary image suitable for VTracerPython.

Important parameters:
- edge_mode
  Allowed values:
  - auto
  - canny
  - foreground_contour
  - stroke_mask

- remove_border_edges
  Whether to remove edge noise touching the image border.

- remove_large_frame_edges
  Whether to remove a large outer frame.

Current auto-mode behavior:

1. Try _extract_foreground_stroke_mask(original_img)
   - Extract non-white foreground from the grayscale image.
   - Use morphological closing to connect small breaks.
   - Detect and remove a very large outer frame.
   - Remove tiny noise components and border-touching components.

2. If the input looks like normalized grayscale:
   - _image_looks_normalized_grayscale(original_img) returns True.
   - Select stroke_mask automatically.
   - Log:
     [NewParams] edge_mode=auto selected stroke_mask centerline input
   - Set:
     edge_representation = "stroke_mask"

3. If stroke_mask is not suitable:
   - Try foreground_contour.

4. If that is still not suitable:
   - Fall back to Canny.

Why stroke_mask matters:
- Canny on thick strokes produces both sides of each stroke.
- Later edge_contour_tracing may parameterize both sides, causing double-layer geometry.
- stroke_mask treats the thick stroke as one solid foreground object, then centerline skeletonization produces a single-line representation.

======================================================================
6. Automatic edge_contour_tracing Switch
======================================================================

NewParams.parameterize() contains the key logic:

    if "edge_contour_tracing" not in kwargs:
        kwargs["edge_contour_tracing"] = self.__edge_representation != "stroke_mask"

Meaning:
- If the current input representation is a normal edge image:
  edge_contour_tracing=True
  VTracerPython may trace edge contours into paths.

- If the current input representation is stroke_mask:
  edge_contour_tracing=False
  Boundary tracing is disabled and the algorithm uses centerline skeletonization instead.

This is the core fix for "thick strokes become two-layer parameterized structures."

======================================================================
7. CurveParameterizer Responsibilities
======================================================================

CurveParameterizer is the adapter between NewParams and VTracerPython.

Main responsibilities:

1. Prepare the trace input image
   - Default trace_source="edges".
   - Writes the NewParams edge/mask image as repair_fig_trace_input.png.

2. Build TraceConfig
   Important configuration fields include:
   - trace_style="centerline"
   - mode="spline"
   - fit_tolerance
   - resample_step
   - filter_speckle
   - gaussian_sigma
   - semantic_window_size
   - keypoint_angle_threshold_deg
   - dp_complexity_weight
   - dp_max_segment_points
   - line_merge_angle_deg
   - arc_radius_rel_tol
   - arc_center_tol
   - arc_min_sweep_deg
   - spline_ctrl_penalty
   - centerline_trace_edge_contours

3. Call VTracerPython
   - VTracerPython(cfg).to_svg(svg_path)

4. Load outputs
   - repair_fig_metrics.json
   - intermediates/component_xxx/semantic_debug.json

5. Build a unified JSON payload
   - save_json() writes curve_parameterization.json.

6. Generate visualization
   - visualize() writes curve_parameterization.png.

======================================================================
8. VTracerPython Centerline Semantic Parameterization
======================================================================

VTracerPython is the actual algorithm implementation.

High-level flow:

    VTracerPython.to_svg()
        -> _to_centerline_svg()
            -> _binarize_foreground_mask()
            -> skeletonize / edge contour trace
            -> split connected components
            -> convert skeleton graph to ordered paths
            -> _resample_polyline()
            -> _fit_centerline_path()

Semantic fitting core:

    _fit_centerline_path()
        -> smooth path
        -> detect keypoints
        -> create candidate boundaries
        -> over-segment path
        -> dynamic programming over line/arc/spline
        -> merge compatible neighboring segments
        -> output semantic_debug.json

Per-segment model selection:

    _fit_segment_model()
        -> try line
        -> try arc
        -> try spline
        -> choose the model with acceptable error and lower complexity cost

Primitive output types:
- line
  For straight segments.

- arc
  For circular arc segments.

- spline
  For more complex curves, usually B-spline-like curve segments.

9. curve_parameterization.json Structure
======================================================================

Top-level fields:

- backend
  Usually "vtracer_python".

- trace_image_path
  The image actually passed into VTracerPython.

- svg_path
  SVG output path.

- metrics_path
  Metrics JSON path.

- metrics
  Overall quality metrics.

- components
  List of parameterized connected components.

Typical component fields:

- component_id
- component_dir
- debug_path
- closed
- sampled_point_count
- resampled_points
- smoothed_points
- raw_keypoints
- refined_keypoints
- keypoints
- global_lines
- segments
- debug

Typical segment fields:

- segment_id
- kind / type
  line, arc, or spline.

- start_idx / end_idx
  Start and end indices in resampled_points.

- effective_params
  Number of effective parameters used by this segment.

- max_error / mean_error
  Segment fitting errors.

- Other model-specific fields
  Concrete line/arc/spline parameters are generated by vtracer_python.py.

10. Debug Logs to Check First
======================================================================

NewParams logs:

- [NewParams] edge_mode: auto
- [NewParams] edge_mode=auto selected stroke_mask centerline input
- [NewParams] edge pixels: ...
- [NewParams] edge representation: stroke_mask

CurveParameterizer logs:

- trace image
- output dir
- metrics path
- fit_tolerance
- resample_step
- edge_contour_tracing
- components
- semantic segments
- by kind
- max_component_error_px

If logs show:

    edge representation: stroke_mask
    edge_contour_tracing=False

then thick strokes are not being traced as double boundaries.

If logs show:

    edge representation: edge
    edge_contour_tracing=True

then the current run is using edge contour tracing. This may be suitable for thin edge maps, but it can be wrong for thick grayscale repair images.

11. Common Failure Modes and Fix Directions
======================================================================

Problem A: Thick strokes become double-layer structures.

Cause:
- Canny detects both sides of a thick stroke.
- edge_contour_tracing=True parameterizes both boundaries.

Fix:
- Use edge_mode="auto" or edge_mode="stroke_mask" for grayscale repair images.
- Confirm edge_representation=stroke_mask in the logs.
- Confirm edge_contour_tracing=False.

Problem B: Lines have gaps and component count is too high.

Possible causes:
- Foreground mask is broken.
- Skeleton branches are split into multiple paths.
- Skeleton endpoints are not merged.

Possible fixes:
- Strengthen morphological closing in _extract_foreground_stroke_mask().
- Add endpoint connection in the skeleton graph stage.
- Merge nearby endpoints at the component/path level.
- Inspect intermediates/mask_binary.png and mask_skeleton.png.

Problem C: Long arcs are classified as lines.

Possible causes:
- Too few sampled points or DP cost favors line.
- arc_min_sweep_deg, arc_radius_rel_tol, or dp_complexity_weight are not suitable.

Possible fixes:
- Reduce resample_step to sample arcs more densely.
- Tune arc_radius_rel_tol, arc_center_tol, and arc_min_sweep_deg.
- Reduce overly aggressive line merging.

Problem D: Too many spline segments and too many parameters.

Possible causes:
- line/arc fitting thresholds are too strict.
- spline_ctrl_penalty is too low.

Possible fixes:
- Increase fit_tolerance moderately.
- Increase spline_ctrl_penalty.
- Strengthen line/arc post-merge logic.

Problem E: Large outer frame is parameterized.

Cause:
- The outer frame was not removed in preprocessing.

Fix:
- Keep remove_large_frame_edges=True.
- Tune large_frame_span_ratio.
- Inspect large-frame removal in _extract_foreground_stroke_mask().

12. Main Tuning Entry Points
======================================================================

NewParams-side:

- edge_mode
  auto / canny / foreground_contour / stroke_mask.

- blur_kernel_size
  Gaussian blur kernel before Canny.

- morph_kernel_size, dilate_iterations, erode_iterations
  Morphological processing for edges or masks.

- remove_border_edges, remove_large_frame_edges
  Remove border noise and large outer frames.

CurveParameterizer / TraceConfig-side:

- fit_tolerance
  Overall fitting error tolerance.

- resample_step
  Arc-length resampling interval. Smaller values produce denser samples and can improve arc detection, but cost more.

- gaussian_sigma
  Path smoothing strength.

- semantic_window_size
  Window size for semantic boundary/keypoint detection.

- keypoint_angle_threshold_deg
  Corner detection threshold.

- dp_complexity_weight
  Dynamic-programming penalty for model complexity.

- dp_max_segment_points
  Maximum number of points in one DP segment.

- line_merge_angle_deg
  Angle threshold for merging neighboring line segments.

- arc_radius_rel_tol, arc_center_tol, arc_min_sweep_deg
  Arc detection and merge parameters.

- spline_ctrl_penalty
  Complexity penalty for spline control points.

13. Recommended Reading Order for an LLM
======================================================================

If a model needs to quickly understand and modify this pipeline, read in this order:

1. Read this file first.

2. Read Rebuild/NewParams.py:
   - NewParams._extract_edges()
   - NewParams._extract_foreground_stroke_mask()
   - NewParams.parameterize()
   - CurveParameterizer.parameterize()
   - CurveParameterizer.save_json()
   - CurveParameterizer.visualize()

3. Then read vtracer_python.py:
   - TraceConfig
   - VTracerPython.to_svg()
   - _to_centerline_svg()
   - _fit_centerline_path()
   - _fit_segment_model()
   - _dynamic_programming_segments or related DP functions
   - _merge_semantic_segments()

4. To adjust the full pipeline:
   - Read _parameterize_repair_image() in fss_parameterized_cst_pipeline.py.

5. To adjust CST geometry construction:
   - Read parameterized_json_to_cst.py.

======================================================================
14. Current Status Summary
======================================================================

The current pipeline has fixed:
- Thick grayscale repair strokes are no longer parameterized as double-layer structures.
- auto mode prioritizes stroke_mask when the input looks like a normalized grayscale repair image.
- stroke_mask automatically disables edge_contour_tracing.
- Logs explicitly show whether the current representation is edge or stroke_mask.

Remaining areas that may need improvement:
- Centerline skeleton endpoint connection.
- Component/path merging around branch points.
- More stable line-vs-arc model selection.
- Adaptive parameter tuning across different datasets.
