1. 总览
======================================================================

根目录当前主要测试脚本：

1. test_clean_parametric_segmentation_validation.py
   测试 clean_parametric_dataset_50 上的“参数化分段质量”。
   重点关注 VTracer 语义分段是否接近 GT：分段点、段类型、有效参数量。

2. test_curve_fit_metamaterial_antenna.py
   测试超材料/天线图像上的图像处理、轮廓提取、曲线拟合与方法对比。
   覆盖 BSpline、NURBS、OptimizedNURBS、OptimizedBS 等传统/优化拟合方法。

3. test_curve_fit_validation_dataset.py
   在 validation_dataset 上测试曲线拟合方法。
   结构参考 test_curve_fit_metamaterial_antenna.py，但面向已有验证集批量样本。

4. test_edge_detect_validation_dataset.py
   在 validation_dataset 上测试边缘检测方案。
   对比原始边缘检测、几何感知边缘提取、GT 边缘等。

5. test_vtracer_centerline_system.py
   Pytest smoke / regression 入口。
   它本身不实现参数化，而是调用 test_vtracer_validation_dataset.run_batch 快速检查 VTracer 中心线系统是否能跑通。

6. test_vtracer_validation_dataset.py
   在 validation_dataset 上系统测试 VTracer 中心线参数化。
   关注骨架中心线、语义分段、line/arc/spline 拟合、SVG 与 metrics 输出。

2. test_clean_parametric_segmentation_validation.py
======================================================================

测试对象：
- vtracer_python.py 中的中心线语义参数化流程。
- clean_parametric_dataset_50 数据集上的分段准确性。
- 新增实验分支 optimized_bs_vtracer：先 OptimizedBSplineFitter，再 VTracer 语义分段。

它不是底层算法本体，而是“参数化分段评估器”。

核心流程：
1. 读取 clean_parametric_dataset_50/summary.json。
2. 对每个样本读取 image 和 GT JSON。
3. 构造 TraceConfig。
4. 调用 VTracerPython.to_svg()。
5. 从 intermediates/component_xxxx/semantic_debug.json 中读取预测 primitive。
6. 与 GT 对比：
   - 分段边界位置是否接近。
   - line / arc / spline 类型序列是否一致。
   - effective_params 是否足够简洁。
7. 输出 clean_parametric_segmentation_report.json。
8. 可选输出每个样本的 *_segmentation_result.png。

主要测试指标：
- breakpoints_mae_ratio
  GT 分段点到预测分段点的归一化平均距离，越小越好。

- breakpoints_count_error
  分段数量偏差 abs(gt - pred)，越小越好。

- type_lcs_score
  预测段类型序列与 GT 段类型序列的 LCS 相似度，越大越好。

- effective_params_pred / effective_params_gt
  预测有效参数量与 GT 启发式有效参数量。

- parsimony_score
  简洁度分数。

- param_score
  综合分数：边界 + 类型 + 简洁度。

重要函数：
- _eval_single()
  单个样本评估入口。

- run_eval()
  批量评估入口。

- run_eval_optimized_bs_vtracer()
  新增实验入口：先 optimized_bs，再把拟合 polyline seed 送入 VTracer。

- diff_segmentation_reports()
  对比两份已经生成的 report，不重新跑评测。

重要命令：

    D:\Python\python.exe test_clean_parametric_segmentation_validation.py

只跑前 10 个样本，不保存 PNG：

    D:\Python\python.exe test_clean_parametric_segmentation_validation.py --max-samples 10 --no-png

运行新实验流程：

    D:\Python\python.exe test_clean_parametric_segmentation_validation.py --pipeline optimized_bs_vtracer --max-samples 10

对比两份报告：

    D:\Python\python.exe test_clean_parametric_segmentation_validation.py --diff-report baseline.json tuned.json

主要输入：
- clean_parametric_dataset_50/summary.json
- clean_parametric_dataset_50/images/*.png
- clean_parametric_dataset_50/gt/*.json

主要输出：
- clean_parametric_eval_output/clean_parametric_segmentation_report.json
- 每个样本的 SVG、metrics、可视化 PNG。
- optimized_bs_vtracer 分支还会输出 optimized_bs_seed_polyline.npy 和 optimized_bs_seed_meta.json。

3. test_curve_fit_metamaterial_antenna.py
======================================================================

测试对象：
- 超材料/天线结构图像的生成、图像预处理、曲线拟合和多方法对比。
- 重点覆盖传统拟合与优化拟合方法：
  - ImageInitializer
  - BSplineContour
  - NURBSpineContour
  - OptimizedBSplineFitter
  - OptimizedNURBSFitter
  - CurveEvaluator
  - GeometryAwareMetrics
  - SegmentExtractor
  - ColorDetector
  - Curves2Components

这个文件更像“综合实验台”，不是单一单元测试。

核心类：
- MetamaterialAntennaTestGenerator
  负责生成测试图像和 GT 几何。
  可以生成矩形贴片、圆形贴片、环形、槽线、弧形槽、曲线组合、FSS 单元、天线结构、复杂分形结构等。

- MetamaterialAntennaTester
  负责对图像执行处理和拟合方法对比。
  会运行多个方法，计算统计指标，生成可视化和报告。

核心流程：
1. 生成或读取测试图像。
2. 使用 ImageInitializer 做居中、边缘提取等预处理。
3. 调用多种曲线拟合器：
   - BSplineContour
   - NURBSpineContour
   - OptimizedNURBSFitter
   - OptimizedBSplineFitter
4. 可选做颜色检测。
5. 可选做 Curves2Components 材料/组件映射。
6. 统计各方法轮廓数量、误差、语义准确性、参数化摘要。
7. 输出对比图和 JSON 报告。

主要测试目的：
- 判断曲线拟合方法对超材料/天线几何的适配程度。
- 对比 B 样条、NURBS、优化 B 样条、优化 NURBS 的拟合质量。
- 评估边界/曲线提取是否适合后续参数化或 CST 建模。

常用命令：

    D:\Python\python.exe test_curve_fit_metamaterial_antenna.py

指定输出目录：

    D:\Python\python.exe test_curve_fit_metamaterial_antenna.py --output test_metamaterial_output

测试指定图像：

    D:\Python\python.exe test_curve_fit_metamaterial_antenna.py --image path\to\image.png

生成/使用验证数据：

    D:\Python\python.exe test_curve_fit_metamaterial_antenna.py --generate-validation

主要输入：
- 内置生成的超材料/天线样例。
- 指定的外部图片。
- 可选 validation_dataset。

主要输出：
- 方法对比图。
- 拟合结果可视化。
- JSON 报告。
- 各方法统计表。

注意：
- 该脚本导入 NURBS 相关模块，环境缺少 geomdl 时，部分 NURBS/OptimizedNURBS 路径可能失败。
- 如果只关注当前 VTracer 参数化，不应优先改这个文件；它主要提供传统/优化曲线拟合实验素材。

4. test_curve_fit_validation_dataset.py
======================================================================

测试对象：
- validation_dataset 数据集上的曲线拟合效果。
- 面向已有验证集样本，而不是手工生成单个超材料/天线图。

主要测试目的：
- 在标准验证集上比较不同曲线拟合算法。
- 观察不同复杂度图形上的拟合稳定性。
- 为优化传统曲线拟合器提供批量评估依据。

主要输入：
- validation_dataset/summary.json
- validation_dataset 中的 images 和 GT。

主要输出：
- 样本级方法对比图。
- 曲线拟合报告 JSON。
- 方法综合统计表。

7. test_vtracer_validation_dataset.py
======================================================================

测试对象：
- validation_dataset 上的 VTracer 中心线参数化完整系统。
- 比 test_vtracer_centerline_system.py 更完整、更重。

核心流程：
1. 读取 validation_dataset/summary.json。
2. 对每个样本构造 TraceConfig。
3. 调用 VTracerPython.to_svg()。
4. VTracer 内部执行：
   - 二值化。
   - 中心线骨架化。
   - 骨架路径转有序折线。
   - 重采样。
   - 关键点检测。
   - 动态规划语义分段。
   - line / arc / spline 拟合。
   - SVG 与 metrics 输出。
5. 读取 metrics。
6. 汇总 batch_summary。
7. 输出 overall visualization、worst case dashboard、top error reports。

主要指标：
- semantic_segment_count
- line / arc / spline 段数
- keypoints
- rmse_px
- mean_error_px
- max_error_px
- metrics_skipped
- skip_rate

注意：
- GT 外轮廓语义段数只作为复杂度参考。
- 中心线不一定与 GT 外轮廓一一对应，因此这里不是严格的 GT 分段对齐评测。
- 如果要严格比较分段边界和类型，应看 test_clean_parametric_segmentation_validation.py。

常用命令：

主要输入：

- validation_dataset 样本图像和 GT。

主要输出：
- 每个样本的 SVG。

10. 2026-05-21 FSS 参数化到 CST Pipeline 维护记录
======================================================================

本节记录最近为 FSS/天线图像清洗、几何参数化、CST 建模仿真主流程做的工程修改。
后续每次修改 pipeline、参数化、CST 重建或相关测试逻辑时，都应同步追加本文件和
TEST_FILES_OVERVIEW_EN.txt，方便后续维护和回溯。

涉及的主要文件：
- fss_parameterized_cst_pipeline.py
  端到端主流程：读取 Instance JSON / inline 配置，FSS 图像清洗，repair_fig.png 参数化，
  再调用 parameterized_json_to_cst.py 进入 CST 建模与仿真。

- geometry_driven_parameterizer.py
  geometry_primitives 参数化后端。它以 VTracer/NewParams 的中心线结果为输入，
  B-spline 只作为中间层，最终输出 line / arc / spline primitives，并保留 sampled fallback points。

- parameterized_json_to_cst.py
  CST JSON 重建入口。现在优先消费 components[*].primitives；若 primitives 不可用，则回退到
  resampled_points / fallback_points，保证 CST 可建模。

当前 pipeline 模式：
- PARAMETERIZATION_MODE = "standard"
  稳定保底流程：repair_fig.png -> NewParams -> VTracer -> curve_parameterization.json。

- PARAMETERIZATION_MODE = "geometry_primitives"
  新几何压缩流程：repair_fig.png -> 自适应边缘输入选择 -> VTracer centerline ->
  B-spline 中间层质量检查 -> primitive decomposition -> compact JSON -> CST。

关键修改摘要：
1. 保留 standard 作为保底路径。
   geometry_primitives 失败时，fss_parameterized_cst_pipeline.py 会回退到 standard。
   若 geometry_primitives 内部判断拓扑不适合压缩，也会输出 standard_NewParams_CurveParameterizer 结果。

2. 增加拓扑保护。
   geometry_primitives 会先检查 VTracer centerline component 数量。
   当前阈值：max_centerline_components_for_geometry = 20。
   如果 component 数量过多，例如 test47 出现 35 个 component，则跳过 B-spline/primitive 压缩，
   直接使用 standard JSON，避免复杂/粗导体结构被错误压缩。

3. 修复 edge_mode 引发的两类问题。
   早期强制 canny 可以恢复旧版细边缘，但会在 test48 这类有线宽结构上产生内外双层边缘。
   后续改为自适应边缘选择：
   - 同时生成 canny 和 auto/stroke_mask 候选；
   - 若 canny 额外边缘与 auto/stroke_mask 在 1-3 px 内长期贴近，则认为是“近距离内外双边伪影”；
   - 此时选择 auto/stroke_mask；
   - 否则保留 canny。
   诊断文件输出到：
   geometry_primitives/01_edges/edge_selection_diagnostics.json

4. 增加 B-spline 质量门。
   对大量直线/直角的 FSS/天线结构，全局闭合 B-spline 会把直角圆滑、把长直线拉弯。
   当前通过以下指标拒绝失真 B-spline：
   - max_bspline_length_shrink_ratio = 0.08
   - max_bspline_rms_error_px = 2.0
   若 B-spline 被拒绝，则使用 corner_preserving_linear_resample_after_bspline_reject，
   即保角的 VTracer centerline 重采样结果作为 primitive decomposition 输入。

5. 增强直线优先策略。
   为减少“本该是直线却被拟合成 arc”的情况，收紧 arc 接受条件：
   - arc_min_sweep_deg = 28
   - arc_min_error_improvement_ratio = 0.55
   - arc_max_radius_to_chord_ratio = 4
   - arc_min_source_points = 24
   同时当 line error 接近可接受范围时拒绝 arc。

6. 可视化输出调整。
   geometry_primitives_preview.png 只显示颜色和起点，不再在图上堆大量文字。
   详细 primitive 信息写入：
   - geometry_primitives/06_preview/primitive_labels.json
   - geometry_primitives/06_preview/primitive_labels.csv

重要调试样例：
- run_20260521_111329
  发现全局 B-spline 把直线拉弯。证据：原始 centerline path length 约 7272 px，
  B-spline 后约 6045 px，缩水约 17%。结论：主要问题在 B-spline 中间层，不是最终 primitive 分类。

- _debug_bspline_guard_111329_b
  验证 B-spline 质量门。B-spline 被拒绝后，直线明显贴回原图。

2026-05-23 Maintenance Addendum: graph_local_primitives Pipeline Flow / 图拓扑局部 primitives 流程维护说明
- Changed files / 修改文件: TEST_FILES_OVERVIEW_CN.txt, TEST_FILES_OVERVIEW_EN.txt.
- Purpose / 目的: document the full pipeline behavior when fss_parameterized_cst_pipeline.py uses:
  "PARAMETERIZATION_MODE": "graph_local_primitives"

graph_local_primitives 的设计目标：
- 替代旧 geometry_primitives 中的“全局 B-spline 中间层”。
- 不对完整 contour / centerline 做全局平滑。
- 先保护拓扑，再做局部几何压缩。
- 局部 primitive 优先级固定为：line > arc > local spline。
- 拓扑正确性优先级高于视觉平滑度。

主 pipeline 入口：
- 文件：fss_parameterized_cst_pipeline.py
- 配置位置：EDITOR_RUN_CONFIG["PARAMETERIZATION_MODE"]
- 推荐配置：
  "PARAMETERIZATION_MODE": "graph_local_primitives"

完整端到端流程：
1. Load Instance JSON
   - 读取 pipeline_test_instance.json 或 CLI 指定的 instance JSON。
   - 输出：
     pipeline_runs/<run>/input_instance.json

2. Image Preparation
   - 若 layer / instance / CLI 设置 skip_fss_cleanup=true，则直接使用 layer img_path。
   - 否则运行 FSSImagePreprocessor，得到 repair_fig.png。
   - 输出：
     pipeline_runs/<run>/image_preparation.json
     pipeline_runs/<run>/prepared_instance.json
     pipeline_runs/<run>/01_fss_clean/.../repair_fig.png（仅未跳过 FSS cleanup 时）

3. Port Summary
   - 完整 fss_parameterized_cst_pipeline.py 会运行 PortSearch，用于后续 CST 端口。
   - 参数化-only 测试脚本 run_parameterization_only.py 会跳过本阶段。
   - 输出：
     pipeline_runs/<run>/port_summary.json
     pipeline_runs/<run>/port_analysis.png

4. Parameterization: graph_local_primitives
   - 调用：
     FSSParameterizedCSTPipeline._parameterize_repair_image_via_graph_local_primitives()
   - 实际类：
     GraphBasedLocalSplineParameterizer
   - 文件：
     geometry_graph_parameterizer.py

graph_local_primitives 内部阶段：
1. Adaptive edge preprocessing
   - 复用 geometry_driven_parameterizer.py 中的自适应 edge/stroke_mask 选择逻辑。
   - 仍保留 sparse auto edge、dense stroke_mask guard、close parallel double-edge diagnostics 等既有保护。
   - 输出：
     02_parameterization/graph_local_primitives/00_edges/edge_selection_diagnostics.json
     02_parameterization/graph_local_primitives/00_edges/newparams_edge_or_stroke_mask.png

2. VTracer centerline extraction
   - 复用 Rebuild/NewParams.py 与 vtracer_python.py 的中心线提取。
   - 输入是选中的 edge/stroke_mask candidate。
   - 输出：
     02_parameterization/graph_local_primitives/00_vtracer_centerline/
     02_parameterization/graph_local_primitives/00_ordered_centerlines/ordered_centerlines_summary.json

3. Topology graph extraction
   - 函数：
     extract_topology_graph()
   - 从 VTracer ordered centerlines 构造 graph。
   - Node 类型：
     endpoint, junction, corner, loop_anchor
   - Edge 字段：
     id, start_node, end_node, ordered_points, length, local_curvature, local_width_estimate, is_closed_loop
   - 检测对象：
     endpoints, T-junctions, X-junctions, loops, branches
   - 重要约束：
     graph 构建阶段不平滑原始像素几何。
   - 输出：
     02_parameterization/graph_local_primitives/01_graph/topology_graph.json
     02_parameterization/graph_local_primitives/01_graph/topology_graph.png

4. Graph edge decomposition
   - 函数：
     split_graph_edges_by_geometry()
   - 按局部几何事件切边：
     tangent angle jump, curvature peak, RDP keypoints, direction change
   - 目标：
     避免 giant full-contour edge；
     让每条 graph edge 尽量对应一个局部稳定几何段。
   - 输出：
     02_parameterization/graph_local_primitives/02_edge_split/split_edges.json
     02_parameterization/graph_local_primitives/02_edge_split/split_edges_preview.png

5. Local geometry analysis
   - 函数：
     compute_geometry_features()
   - 主要指标：
     linearity_score, curvature_variance, arc_consistency, tangent_stability,
     point_density, direction_histogram, length_chord_ratio
   - 直线判断：
     PCA / total least squares；高 lambda1/lambda2 代表强直线候选。
   - 圆弧判断：
     radius stability, curvature sign stability, sweep angle, radial variance。

6. Local primitive fitting
   - 函数：
     fit_local_primitive()
   - 固定优先级：
     line -> arc -> local spline
   - line：
     PCA total least squares + endpoint lock。
   - arc：
     least squares circle；必须比 line 明显更好。
   - local spline：
     只作为局部 fallback；
     open spline only；
     不允许 full contour spline。
   - 每个 primitive 都保留：
     source_edge_id, start_node, end_node, parameters, fallback_points
   - 输出：
     02_parameterization/graph_local_primitives/03_local_fit/edge_xxxx_fit.json
     02_parameterization/graph_local_primitives/03_local_fit/edge_xxxx_fit.png
     02_parameterization/graph_local_primitives/03_local_fit/local_fit_preview.png

7. Topology validation
   - 函数：
     validate_graph_topology()
